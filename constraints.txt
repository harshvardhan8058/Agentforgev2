# Build-time pip constraints for the backend image (Dockerfile) ONLY.
#
# This file is NOT the dependency manifest — the app's declared dependencies live in
# pyproject.toml [project].dependencies and are unchanged. It only bounds a heavy
# TRANSITIVE dependency (`transformers`) to a compatible range so the
# `pip install -r requirements.txt -c constraints.txt` step in the builder stage is
# deterministic and fast (no pathological dependency backtracking). Behavior is identical
# to a normal resolve; this just removes the ambiguity that made pip explore dozens of
# candidate versions and exhaust the CI runner's disk/time.
#
# See the backend image note in docs/INFRASTRUCTURE.md.

# `sentence-transformers` depends on an unpinned `transformers` (it accepts
# >=4.41,<6.0.0); without a constraint pip backtracks across many transformers releases.
# We bound it to a COMPATIBLE RANGE (not an exact pin) that both prevents pathological
# backtracking AND stays portable: it never pins an exact version that might not exist on
# the real upstream PyPI (an exact pin resolved from a local mirror could fail on a
# GitHub-hosted runner).
#
# The LOWER bound is a security floor, not just a compatibility one. `transformers` is on
# the embedding path (it loads model config/weights), and the 4.x line it previously
# pinned to carried 25+ known advisories — the old `<4.48` upper bound sat *below* the
# fix version for most of them, so the image was pinned to a knowingly-vulnerable release
# even after the advisories were published. Keep this floor at an advisory-clean version
# and re-verify with `pip-audit` (see docs/SECURITY_MAINTENANCE.md) before relaxing it.
transformers>=5.14.1,<6.0

# NOTE: torch is NOT resolved from PyPI. The Dockerfile builder stage installs a pinned
# CPU-only build FIRST from the PyTorch CPU wheel index
# (`pip install --index-url https://download.pytorch.org/whl/cpu "torch==2.13.0"`), before the
# `pip install -r requirements.txt -c constraints.txt` step. Because torch is already
# satisfied, the sentence-transformers resolve (which requires torch>=1.11) reuses the
# CPU build instead of pulling the CUDA/NVIDIA PyPI wheel. This removes the multi-GB
# `nvidia-cu*` payload and drops the backend image from ~17.8 GB to well under the 4 GB budget,
# with byte-identical application behavior (no source or app-dependency change). The
# `transformers` bound above still applies to keep the resolve deterministic.
